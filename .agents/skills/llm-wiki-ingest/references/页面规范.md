# 页面规范

## 核心原则

这个知识库不是“材料摘要仓库”，而是一个可追溯、可增量更新的知识网络：

```text
原始材料（0.0 Inbox，只读）
        ↓ 编译
单一来源页（1.0 Material）
        ↓ 综合与链接
2.0 Topics（跨来源知识）
        ↓ 导航
3.0 Maps
```

- 原始材料只读取，不改写、不覆盖、不移动；
- 所有关键判断都能回到来源和具体 locator；
- 新材料优先更新已有 Topic，不为同义词重复建页；
- 不能把单一作者观点写成行业共识；
- 来源互相冲突时保留冲突与各自条件，不强行“统一答案”；
- `目录.md` 与本 Skill 的 `references/导入日志.md` 是每次导入的必更新文件。

## 文件夹职责

```text
0.0 Inbox/       原始材料投递区，默认不进入公开 Git
1.0 Material/    所有单一来源的编译页，不按材料类型拆文件夹
2.0 Topics/      跨来源 canonical 知识页，全部平铺
3.0 Maps/        按稳定领域组织的导航
```

不建立 Playbooks 层。来源支持的方法、诊断问题、步骤和失败信号写进对应 Topic，避免同一知识维护两份。

## 原始材料与去重

- 开始前读取本 Skill 的 `references/导入日志.md`，并搜索文件名、标题、作者、URL、DOI、ISBN 和现有 `source_id`；
- 本地文件可计算 SHA-256 作为 `source_fingerprint`；无法计算时记录可用的稳定标识；
- 同一材料的新版、节选或译文不能静默覆盖旧记录，要注明版本关系；
- 未经用户允许，不把私人、内部或受版权保护的完整原文复制进公开来源页。

## 来源页通用标准

来源页没有固定正文模板。Agent 应先识别材料类型、信息结构和作者的论证方式，再选择最能忠实表达该材料的页面结构。不要为了版式一致，把论文、随笔、访谈和会议记录都压进同一组标题。

统一的是下面这些质量底线，而不是章节名称：

来源页不是固定长度摘要。洞见数量应与材料的信息密度匹配：

- 短文章或短笔记通常 2–5 个独立洞见；
- 中等文章、章节或报告通常 5–12 个；
- 长访谈、长报告或长章节通常 12–25 个，必要时更多。

每个独立洞见尽量保留：

1. 核心判断；
2. 作者或说话人的 reasoning；
3. 原文中的例子、数据或反例；
4. 适用条件、边界或不确定性；
5. 来源 locator；
6. 只在必要时保留最短、直接支撑判断的原文短引。

不得为了凑数量拆分重复点，也不得为了节省 Token 删除独立洞见。

### 最低溯源字段（不是正文模板）

字段按材料实际情况选用；未知信息不得为了填满 metadata 而猜测。

```yaml
type: source
source_id: author-year-short-title
source_type: article
title: 原始标题
author: 作者或机构
published: YYYY-MM-DD
source_file: "[[文件名]]"
external_url: https://...
language: zh-CN
status: imported
imported_at: YYYY-MM-DD
source_fingerprint: sha256:...
insight_count: 8
```

未知字段使用 `unknown` 或留空，不猜测。现有播客页可继续使用 `type: episode`、`guest` 和已有 frontmatter，不要求为了目录改名而机械重写。

### 不同材料的 locator

| 材料类型 | 首选 locator |
|---|---|
| 播客、访谈、会议录音转写 | 说话人 + 时间码范围 |
| 文章、newsletter、网页 | 小节标题 + 段落或原始 URL anchor |
| 论文、报告、PDF | 页码 + 章节，必要时图表编号 |
| 书或书摘 | 章节 + 页码，并注明版本 |
| 内部文档 | 文档版本/日期 + 标题层级或段落 |
| 无稳定结构的纯文本 | 自建段落编号，并标记为弱定位 |

定位缺失不等于可以伪造。无法稳定定位时，在页面和导入报告中明确标注 `weak-locator`。

### 引用标准

- 引用必须属于正确作者或说话人，并直接支持所在判断；
- 原话放在它所支撑的单条洞见内，不再设置页面底部的“值得保留的原话”集中区；
- 不把 Wiki 概括放进引号，不把不连续片段拼成一句话；
- 跨段综合时写“综合判断，无单句原话”；
- 引用不能代替中文综合；

## 播客、访谈与会议转写的附加标准

- 完整阅读文字稿，覆盖 chapters 中全部主要问题；
- 长节目通常保留 15–25 个 insight blocks，并在 chapters 外保留真正有价值的独立洞见；
- 区分嘉宾、主持人、广告和其他说话人；
- metadata 与正文冲突时记录异常，不猜；
- 时间戳和短引文必须能回到原始文字稿核验。

## Topic 标准

Topic 不是术语解释，也不是来源摘要拼接。每页应包含：

- 清晰定义与边界；
- 多来源的共同判断与推理；
- 关键例子或反例；
- 分歧及各自成立条件；
- 与邻近概念的关系；
- 常见误用、失败方式或不适用条件；
- 可追溯来源页 + locator。

只有一个来源时必须明确标注。新增材料只带来补充、反例或修正时，应更新原 Topic，而不是另建近义页。

### Canonical 规则

- 每个概念使用唯一稳定的 `concept_id`；
- 对外只用一个 canonical 名称；英文原词、旧翻译和常见变体进入 `aliases`；
- 建页前同时搜索标题、aliases、`concept_id` 和近义词；
- 只在概念有稳定边界、独立解释价值且无法自然并入现有 Topic 时新建。

这个 12 期 Lenny Sample 的当前领域词表是：

- `product-management`
- `product-strategy`
- `discovery-research`
- `pmf-startup`
- `growth-retention`
- `gtm-monetization`
- `data-experimentation`
- `leadership-organization`

这些是 seed，不是通用知识库的永久上限。个人 fork 可以随语料扩展领域，但应先形成一组稳定 Topic，再建立新 Map，避免每篇材料都创造新分类。

## Map 标准

- 一张 Map 对应一个稳定领域或明确问题空间；
- Map 只放关键问题、阅读路径和 canonical Topics，不复制 Topic 正文；
- Topic 通过 `domains` 进入一个或多个 Map；
- 新领域尚不足以形成清晰路径时，先留在 `目录.md`，不要过早建空 Map。

## 目录与导入日志

每次导入完成后必须：

1. 在 `目录.md` 中新增或更新所有受影响页面的一句话说明；
2. 在本 Skill 的 `references/导入日志.md` 末尾记录日期、材料、指纹或稳定标识、动作、输出页面与异常；
3. 检查本次新增页面至少链接到一个现有页面，或明确记录为什么暂时无法链接。

## 问答与写回

- 回答问题时先查 `目录.md`，再读取相关 Topic 和来源页；
- 清楚区分来源事实、作者观点和 Wiki 的跨来源推断；
- 回答中列出实际使用的 Wiki 页面；
- 有价值的新推论可以建议保存，但未获用户确认前不要写回。

## 维护检查

维护任务至少检查：

- 失效 wikilink；
- 孤立页与未进目录页；
- 重复或高度相似 Topic；
- aliases、`concept_id` 和术语漂移；
- 页面间矛盾、错误归因和过期结论；
- 导入日志、来源指纹与实际文件不一致。

任务结束输出简短报告。删除、合并或大范围改写前先征求用户同意。
