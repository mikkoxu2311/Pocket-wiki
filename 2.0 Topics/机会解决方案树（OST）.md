# 机会解决方案树（OST）

## 结构

```text
Desired Outcome
└── Opportunities
    └── Solutions
        └── Assumption Tests
```

## 用法

1. 先写清希望改变的 outcome。
2. 从研究中整理客户的 needs、pain points 与 desires，形成 opportunity space。
3. 为优先 opportunity 生成多个 solution，而不是过早锁定一个功能。
4. 找出每个 solution 最危险的 assumption。
5. 用最小成本测试 assumption，再决定如何进入 delivery。

## 注意

树是决策地图，不是一次性 workshop 产物。它应随着新研究与测试更新。
